# Cataclysm website, download counting, and usage stats

## Overview

When done: a Cloudflare Worker at `worker/` is deployed on the akshath.me zone serving `/cataclysm/download` (resolve newest release, count, 302 to the DMG) and `/cataclysm/ping` (daily heartbeat into Analytics Engine), forwarding every other `/cataclysm/*` path to GitHub Pages; `worker/stats.sh` prints downloads per day, daily and weekly active installs, jail share and weekly cohort retention from the Analytics Engine SQL API; `make dmg` emits the versioned DMG, its version-stable copy and the updater zip, and stages a plain-text read-me next to the app icon; `make release` is gone; the app sends the heartbeat behind a "Send anonymous usage stats" switch on the panel's main page; the panel's "Check for updates…" row opens `akshath.me/cataclysm`; README's install section points at the website and a privacy section lists every heartbeat field; the landing page exists as `cataclysm/index.md` on branch `cataclysm` of the site repo, in a worktree at `~/code/heyitaki.github.io-cataclysm`, built clean by Jekyll and ready for the user to preview and merge.

The design is `specs/cataclysm-website.md` (every route's exact behavior, the release asset contract, the Analytics Engine schema, the heartbeat fields) plus `specs/auto-update.md` section "Release artifacts and the feed" (the release asset set and the zip producer). Before each task, read the sections it names. Implement; never redesign. The only edits allowed under `specs/` are the ones a task names: queue-row state and notes in `specs/cataclysm-website.md` and `specs/auto-update.md`, hypothesis outcomes, and `specs/progress.md` r.10.
